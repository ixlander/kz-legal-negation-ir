The tokenizer rarely isolates the Kazakh negative affix, yet Kazakh retrieval is not worse

D2 asks whether the tokenizer keeps the Kazakh negative suffix as a separate piece. For example, in төлемейді the part "ме" marks negation. In only 21 percent of 171 real forms does the XLM-R tokenizer cut the word exactly around that suffix. We expected this to hurt Kazakh search. It did not: bge-m3, which uses this same tokenizer, finds the right paragraph for 97 percent of Kazakh negation questions, compared with 79 percent for Russian. So the tokenizer statistic does not predict retrieval quality here. One caveat: many Russian tax questions use abbreviations such as VAT that the law never uses, while the Kazakh versions spell them out, which makes Russian harder for reasons unrelated to negation.
